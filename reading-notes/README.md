```

├── README.md                         # This file - overview & guidance
```

---

## 📚 How This Works

### **Step 1: Get the PDF**
- Go to `../books/` folder
- Find the PDF you want to read
- Download or open it

### **Step 2: Create Summary File**
- Copy `TEMPLATE.md` in this folder
- Rename it: `[book-name]-notes.md`
- Example: `learning-sparql-notes.md`

### **Step 3: Fill as You Read**
- **Key Concepts**: One-sentence summary (after reading intro)
- **Detailed Notes**: Chapter breakdown (as you read each chapter)
- **Real-World Applications**: Connect to your projects (while reading)
- **Questions**: Things to explore deeper (as they come up)
- **Practical Next Steps**: How to apply (after finishing)

### **Step 4: Update Main README**
- Go to `../books/README.md`
- Update the table to mark your book as "✅ Completed"
- Add a link to your `.md` file here

## 💡 Tips for Better Notes

### ✅ DO:
- **Connect to projects**: "In my KIK-V dashboard, I use..."
- **Ask questions**: "Why does RDF use URIs instead of...?"
- **Add code examples**: Copy code snippets you find useful
- **Note page numbers**: "See page 42 for..." (easy reference)
- **Compare concepts**: "Unlike SQL, RDF allows..."

### ❌ DON'T:
- Copy entire paragraphs (summarize instead)
- Write without connecting to your work
- Leave questions unanswered (research them)
- Forget to update the main README when done

## 🎓 Best Practices

### **Reading Strategy**
1. **Skim first**: Read intro/conclusion to understand scope
2. **Read chapters**: Focus on practical sections
3. **Pause to summarize**: After each chapter, write 3-5 key points
4. **Connect immediately**: "How does this apply to my work?"
5. **Ask questions**: Note things you don't understand yet

### **Taking Notes**
```markdown
### 1. [Concept Name]

**What the book says:**
- Point 1
- Point 2

**My understanding:**
[What does this mean to me?]

**How I'll use it:**
[Project application]
```

### **Review & Update**
- Weekly: Update your current summary
- Monthly: Review all summaries for connections
- Quarterly: Build a "cheat sheet" of key concepts

## 🤔 Common Questions

**Q: Should I summarize every book?**  
A: No, only books that are highly relevant to your work. Focus on depth, not quantity.

**Q: How long should a summary be?**  
A: 1-2 pages per book (or per chapter for long books). Enough to refresh your memory later.

**Q: Can I write summaries while reading?**  
A: Yes! Better to capture your thoughts as you read than try to remember them all at the end.

**Q: Should I include code from the book?**  
A: Yes, but annotate it with YOUR understanding and how YOU'D use it.
